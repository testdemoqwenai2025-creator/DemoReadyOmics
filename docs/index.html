The wedge

We don't compete with pipeline runners.
We compete on the handoff to ML.

Existing platforms (Nextflow, Terra, Galaxy, Seqera, nf-core, AWS HealthOmics) are good enough at running workflows. Almost none of them ship datasets that are ready to train on. That handoff — from pipelines to ML — is where Tessera Bio is uniquely good, because it requires deep biology expertise, not just workflow engineering.

U1differentiator
ML-ready outputs

Not just BAMs and VCFs — train-ready matrices.

Every pipeline emits a model-ready matrix plus a dataset card. Train / val / test splits are stratified by biological leakage (held-out donors, families, chromosomes, drugs), not random. The dataset card documents normalisation method, batch effects, known biases, and suggested downstream uses.

  • Leakage-controlled splits by default
  • Dataset card with full provenance
  • Quality metrics + failed-sample list
  • Suggested vs discouraged uses documented
U2differentiator
Cross-release identifier stability

When Ensembl or UniProt release, we tell you what broke.

Every dataset is pinned to a specific Ensembl release, UniProt release, and reference genome build. A built-in identifier-drift report flags genes added, removed, merged, or split between releases — and which downstream models need retraining.

  • Pinned Ensembl / UniProt releases per dataset
  • Identifier-drift report on every release
  • Model-impact assessment: which models need retraining
  • Cryptographic provenance via Sigstore signatures
U3differentiator
Multi-omic harmonisation, native

Genes, transcripts, proteins, metabolites — joined, versioned, first-class.

Most platforms handle one omic well and bolt the others on. Tessera treats genes, transcripts, proteins, metabolites, and pathways as first-class, joined, versioned citizens. A pipeline run can declare 'I need RNA-seq + proteomics + metabolomics for these N patients harmonised to Ensembl v110 / UniProt 2024_01' and the platform handles join keys, missingness, and unit harmonisation.

  • Common biological entity model across omics
  • Automatic join-key resolution
  • Unit and scale harmonisation
  • Per-source attribution pass-through

U2 — Cross-release identifier stability

Identifier drift reports

When Ensembl or UniProt publish a new release, models trained on the previous release silently become un-reproducible. Tessera ships a drift report on every dataset so teams know exactly which models need retraining and why.

New gene IDs present in Ensembl v110 that did not exist in v109. Models trained on v109 will not have features for these genes — they will need to be added to feature vectors with zero-imputation if retraining.

Architecture

From public raw data to ML-ready, signed datasets

The MVP pipeline runs on a single machine with hash-pinned containers. Each stage emits structured metadata that flows into the final dataset card. The pipeline layer itself is open-core (Apache 2.0); the harmonisation and dataset-card generator layers are source-available.

Running MVP code (private repo)

Not just a demo — there is actual code behind this

The Tessera Bio MVP is implemented as a Python pipeline + Nextflow workflow + CLI. The code lives in the private repository (ReadyOmics1-Advance). The public repo (DemoReadyOmics) mirrors only the public-facing subset. Everything below is what an evaluator would see in a private technical review.

CLI

A single entry point for the pipeline. Sub-commands mirror the Nextflow stages so either can be used.

$ tessera build \
    --config configs/gtex-breast.yaml \
    --output-dir output/

[1/7] Parsing cohort config...
[2/7] Harmonising against Ensembl v110...
[3/7] Batch correction (ComBat-seq)...
[4/7] Generating leakage-controlled splits...
[5/7] Identifier drift report...
[6/7] Generating dataset card...
[7/7] Signing provenance manifest...

10 sub-commands: parse-config, ingest,harmonise, correct-batch, splits,drift-report, generate-card,sign, verify, build.

Nextflow workflow

Single-machine orchestration in v0.1; portable to cloud in v0.2. All containers are hash-pinned for reproducibility.

nextflow run main.nf \
  -profile docker \
  --config configs/gtex-breast.yaml \
  --output-dir output/

Stages:
  1. IngestSample   (per-sample)
  2. RunQC           (fastp)
  3. Align           (STAR 2.7.11b)
  4. Quantify        (salmon 1.10.1)
  5. Harmonise       (Ensembl v110 + DESeq2 vst)
  6. CorrectBatch    (ComBat-seq)
  7. GenerateSplits  (U1 leakage control)
  8. IdentifierDrift (U2 diff report)
  9. GenerateCard    (U1 + U2)
 10. SignManifest    (Sigstore)
